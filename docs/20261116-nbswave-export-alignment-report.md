# 导出链路对齐 nbswave + 播放落点列派发 实测报告

- 结论：导出三件（电平 / 时间轴 / 声像）已对齐打包版 nbswave 0.4.0；真曲 A/B 时长差约 2 ms、起始差 0.1 ms、50 ms 包络相关 0.9990。
- 播放键起播现在会「落点列派发」（变速器 / 消音器 / 音符立刻生效），对齐原版 `toggle_playing`；录音待命首键起播同语义。
- CLI 导出补上自定义乐器采样加载（此前 `--export-wav` / `--export-audio` 漏载自定义音色）。
- 全仓 200 个测试通过；本轮 5 个本地提交（未推送）。
- 日期 / 环境：2026-11-16，Windows 单机实测；样本 = 1 首真曲 + 合成用例，非统计样本。

## 2. 改动前后

### 2.1 改版前

- 导出：我们自加了限幅（软削波）、导出余量（headroom）、主音量乘算三个原版没有的行为；音符定位按「歌头 + 固定每刻时长」线性排布，变速器不改导出时间轴；声像用实时播放那套线性曲线；长度只按混音用的音符算。
- 播放：按播放键只是「开始走表」，落点列上的变速器 / 消音器 / 音符要等播放头跨到下一列才生效——从落点列直接起播时，变速不生效、该列不出声、消音器不消音。
- CLI：`--export-wav` / `--export-audio` 只扫内置采样目录，歌里带自定义乐器的曲子导出缺声部。

### 2.2 改版后

- 电平：只保留 nbswave 行为——峰值 > 1 时整轨除以峰值归一到 0 dBFS，否则一个样本都不动。限幅 / 余量 / 主音量三个偏差整体删除，首选项注释同步（原版没有这些开关）。
- 时间轴：离线渲染按 `tempo_segments` 语义定位——逐刻累计 `1/当前速度` 得到每刻的实际发声时刻；照抄两处原版行为：第 0 刻晚一步落位（`segments[0] = 1/tempo`）、同刻多枚变速器最后一枚生效。导出长度按**全部**音符（含锁定层）的结尾最大值算（nbswave `get_length` 对 weighted_notes 求最大，混音才过滤锁定层）。
- 声像：导出改用 pydub pan 曲线（原版导出链路实际走的公式）：增益提升量 `|pan|·20·log10(2)` dB 且**只放一半**，另一侧按 `2 − 增益倍率` 线性减；极左 / 极右 = (2^0.25, 0) / (0, 2^0.25)。层声像混合 `(层声像 + 音符声像)/2` 与实时一致。
- 播放：调度器新增 `tempo_at_tick`（变速点表取值：≤ 落点刻的最后一枚生效，同刻末枚覆盖，锁定层变速器照常参与）与 `dispatch_landing_column`（落点列整列派发：变速器改速、消音器掐区间、音符发声）；循环回绕后同样补播落点列（原版 `control_step` diff<0 分支）。编辑器「播放 / 暂停」与录音待命首键两条起播路径改走 `AudioEngine::start`，不再直接 play。

### 2.4 没有改什么

- 实时播放的声像保持原样：原版实时走 GameMaker emitter（`audio_emitter_position`），导出走 pydub，**本来就是两条曲线**；我们实时仍是线性 pan，只改了导出侧。
- 首选项里没有新增任何开关——原版没有的参数（限幅、时间轴、声像曲线）不进配置。
- 循环 / 结尾停止的时钟行为（非循环播到歌长 +16 刻停、循环按次数回绕）未动。
- 混音内核（f32 累加、Voice 复用）未动；只改电平终处理、定位与声像系数。

### 2.5 代价

- 离线渲染多一步全曲 `tempo_segments` 计算（每刻一次浮点累加，毫秒级）与事件表两遍构建（计长一遍含锁定层、混音一遍按开关），实测对 193 s 真曲导出耗时可接受（见 §3 表格之外的观感，无专门基准）。
- 起播派发让「按播放键」多派发一列事件（最多几百枚音符的建声开销），与原版同代价。

## 4. 各项对齐细节

### 4.1 电平（#43）

- 打包版终处理源码：`peak = max(abs)`，`clipping_factor = peak/32767`，> 1 才整轨除峰；`headroom` 参数是死的（不参与）。我们删掉三个自加行为后与之一致，合成用例（1.8 峰 → 归一到 1.0；0.9 峰 → 原样）+ 真曲对照（双侧峰值 1.0000）验证。

### 4.2 时间轴（#44）

- `segments[0] = 1/tempo`：原版第 0 刻的时长晚一步计入，tick 0 的音符起始位置不是 0 秒而是 `1/tempo` 秒。已照抄并有测试钉住（tick-0 起始 = 0.1 s @ 10 t/s）。
- 同刻多枚变速器：最后一枚生效（原版 pop+push）。锁定层变速器照常进表（原版 `update_tempo_changes` 不看层锁）。
- 导出长度：按全部音符（含锁定层）结尾最大值；全空时退回歌长静音（原版此处直接崩，见 §6）。

### 4.3 声像（#48）

- pydub 0.25.1 `pan` 公式逐项移植：提升 dB 的一半进增强侧（极值 2^0.25 ≈ +3.01 dB），衰减侧 = 2 − 增益倍率（极值归 0）。测试断言：居中 (1,1)、±0.5 → (2−√2, 2^0.25)、极值 (0, 2^0.25)/(2^0.25, 0)。

### 4.4 落点列派发（#45）

- 原版语义（tag v3.12.0-rc.1）：`toggle_playing` 起播分支 `tempo = get_tempo_from_tick(floor(marker_pos))` 无条件执行，随后整列派发（变速器 → 消音器 → 音符；变速器派发时再按 `floor(|pitch|)/15` 覆盖一次）；暂停分支只重置循环计数，不派发。
- 我们的落点：`AudioEngine::start(from_tick)` = seek + play + `dispatch_landing_column`；编辑器两个起播入口（`Command::PlayPause`、录音待命首键 `draw_piano.gml:147` 对应路径）都改走它。空格键 / 工具栏 / 图标条最终都汇到 `Command::PlayPause`，无旁路。
- 循环回绕：原版回绕后 `diff < 0`，`control_step` 补播落点列——我们在回绕分支里同样调 `dispatch_landing_column`，回绕列上的消音器能把上一轮残留发声掐掉（测试钉住）。
- 新增测试 3 个：`pressing_play_dispatches_landing_column`、`tempo_at_tick_walks_the_changer_table`（含锁定层变速器）、`loop_wrap_redispatches_landing_column`。

## 5. 边界件

- **空歌**：nbswave 渲染空歌直接抛 ValueError 崩掉；我们导出「歌长长度的静音」。这是有意保护，不是对齐（原版行为是崩溃，不值得复刻）。
- **变速器 pitch 越界**：`.nbs` 格式 pitch 本身是 i16，`tempo = floor(|pitch|)/15` 无越界面；负 pitch 照原版取绝对值。
- **极多层歌**：209 层真曲全量加权渲染正常；与原版实时播放的 endb2 门差异见 §8 拍板项。

## 6. 剩余差异（瓶颈与风险）

1. **重采样**：nbswave 每音符经 pydub（audioop.ratecv）变速，我们是线性插值——包络相关 0.9990 里主要剩下的一项，听感上不可辨但波形不逐样本相等。
2. **量化路径**：nbswave 把每个音符转 int16 后按 int32 累加（最后一刻才转回浮点），我们全程 f32 累加。量化噪声级差异。
3. **纯视觉事件乐器**：原版跨列派发的 else-if 链里还有 Toggle Rainbow / Show Save Popup / Change Color to #… / Toggle Background Accent（改界面配色、弹提示）。我们跨列派发与落点派发都只处理「出声类」（变速器 / 消音器 / 音符），视觉类没接——属 UI 侧另行任务，不在本轮拍板范围。
4. **播完停在结尾再按播放**：非循环模式下停在「歌长 + 16 刻」，此前再按播放会原地起播立刻再停；原版此时回 0 起播（`marker_pos == enda + cols` 判等）。**已补**（`e9ce56e`）：起播统一走 `begin_playback`，停在结尾先回 0。

## 8. 下一步（含拍板项）

1. **【拍板】尾部空层的 endb2 可见行数门要不要复刻？**
   原版事实：图层面板每帧把「可见空行」初始化为默认值并把 `endb2` 抬到可见范围（control_draw.gml:1305），而实时播放的音量 / 声像加权只对层号 < endb2 生效（control_step / toggle_playing 的 `if (b < endb2)`）。后果：打开多层歌**不把图层面板滚到底就播放**时，没被面板见过的层按错误权重发声（音量≈1、声像 0）——原版实时播放的 bug；导出引擎 nbswave 没有这层门，权重全量正确。
   - 选项 1（建议）：**不复刻**。实时播放保持现在的全量正确加权（与导出一致、与原版意图一致）。代价：与原版在「多层歌打开即播」场景可听差异（原版底下层几乎无声）。
   - 选项 2：复刻。需要把 UI 可见行数接进调度器（跨线程耦合），且复刻的是原版自身 bug，同时会出现原版同款「播放与导出不一致」。
2. ~~【可顺手补】播完停在结尾再按播放 → 回 0 起播~~ **已完成**（`e9ce56e`，报告成文当场补掉）。
3. 纯视觉事件乐器（Rainbow / 改色 / 存档弹窗）在播放调度中的接线——属 T4 UI 侧，排到后续。

## 9. 一句话总结
